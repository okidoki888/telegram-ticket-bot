# Руководство по использованию Telegram Ticket Bot

## Основная функциональность

Бот автоматически переносит сообщения из исходных тредов в выделенный тред при добавлении реакции на сообщение.

## Принцип работы

1. **Отслеживание реакций**: Бот мониторит все реакции в настроенных тредах-источниках
2. **Фильтрация**: Проверяет соответствие паттерну заявки (если настроен)
3. **Перенос**: Копирует/пересылает сообщение в тред назначения
4. **Логирование**: Записывает информацию в БД и Google Sheets
5. **Подтверждение**: Отправляет уведомление "Закрыто" в исходный тред

## Настройка в Telegram

### 1. Настройка тредов

В конфигурации укажите:
- `SINK_TOPIC_ID` - ID треда куда переносить заявки
- `SOURCE_TOPIC_IDS` - список ID тредов откуда принимать заявки

### 2. Права бота

Бот должен иметь права администратора с разрешениями:
- ✅ Отправка сообщений
- ✅ Удаление сообщений
- ✅ Чтение всех сообщений

### 3. Получение ID тредов

Используйте [@userinfobot](https://t.me/userinfobot):
1. Добавьте бота в группу
2. Отправьте сообщение в нужный тред
3. Переслайте это сообщение боту в личные сообщения
4. Получите `message_thread_id`

## Процесс обработки заявки

### Для пользователей

1. **Создайте заявку** в одном из исходных тредов
2. **Поставьте любую реакцию** на сообщение с заявкой
3. **Получите подтверждение** "Закрыто" в том же треде
4. **Найдите заявку** в треде назначения

### Для администраторов

1. **Мониторинг**: Отслеживайте обработку через Grafana
2. **Логи**: Проверяйте детальные логи в базе данных
3. **Статистика**: Анализируйте данные в Google Sheets

## Конфигурация поведения

### Режим переноса (`CLOSE_TRANSFER_MODE`)

- `copy` - копирует сообщение (сохраняет оригинал)
- `forward` - пересылает сообщение (показывает автора)

### Подтверждение (`REPLY_ACK`)

- `true` - отправляет "Закрыто" в исходный тред
- `false` - тихая обработка без уведомлений

### Отладка (`DEBUG_VERBOSE`)

- `true` - подробные логи и уведомления
- `false` - только основные события

### Фильтр заявок (`TICKET_PATTERN`)

Регулярное выражение для проверки текста:
```bash
# Пример: сообщения начинающиеся с "Заявка: номер"
TICKET_PATTERN=(^|\\n)Заявка:\\s*\\d+

# Пример: любые сообщения содержащие слово "заявка"
TICKET_PATTERN=(?i)заявка

# Отключить фильтр (принимать все)
TICKET_PATTERN=
```

## Мониторинг и логирование

### Доступ к мониторингу

- **Grafana**: `https://your-domain.duckdns.org/grafana/`
- **Prometheus**: `https://your-domain.duckdns.org/prometheus/`
- **Метрики**: `https://your-domain.duckdns.org/metrics`

### Ключевые метрики

- `telegram_bot_tickets_processed_total` - количество обработанных заявок
- `telegram_bot_reactions_received_total` - количество полученных реакций
- `telegram_bot_webhook_requests_total` - количество webhook запросов
- `telegram_bot_reaction_processing_duration_seconds` - время обработки

### Логи в базе данных

Таблица `telegram_bot.ticket_logs` содержит:
- Детали всех обработанных заявок
- Время обработки
- ID пользователей и тредов
- Текст сообщений и тип медиа

### Google Sheets логирование

Автоматически записывает в таблицу:
- Дату и время
- Исходный и целевой треды
- Пользователя
- Тип контента
- Текст сообщения

## Команды управления

### Статус сервиса

```bash
# Проверка состояния контейнеров
docker-compose ps

# Логи всех сервисов
docker-compose logs -f

# Логи конкретного сервиса
docker-compose logs -f telegram-bot
```

### Управление

```bash

# Перезапуск конкретного сервиса

```


## Устранение неполадок

### Бот не реагирует на реакции

1. **Проверьте права бота** в группе
2. **Убедитесь в корректности тредов** в конфигурации
3. **Проверьте webhook** статус: 
   ```bash
   curl "https://api.telegram.org/botTOKEN/getWebhookInfo"
   ```

### Сообщения не переносятся

1. **Проверьте паттерн заявки** - возможно слишком строгий
2. **Проверьте логи** на наличие ошибок:
   ```bash
   docker-compose logs telegram-bot | grep ERROR
   ```
3. **Убедитесь в доступности треда назначения**

### Проблемы с SSL

1. **Проверьте сертификаты**:
   ```bash
   docker-compose exec nginx ls -la /etc/letsencrypt/live/
   ```
2. **Обновите сертификаты**:
   ```bash
   docker-compose run --rm certbot renew
   ```

### Высокое потребление ресурсов

1. **Проверьте размер логов**:
   ```bash
   du -sh logs/
   ```
2. **Очистите старые данные**:
   ```bash
   docker-compose exec postgres psql -U bot_user -d telegram_bot -c "SELECT telegram_bot.cleanup_old_logs(30);"
   ```
